# At-Turath Academy — সিস্টেম ডিজাইন (খসড়া)

At-Turath Academy একটা **অনলাইন** একাডেমি। এর কোনো শারীরিক ক্লাসরুম নেই, ক্লাস হয় Zoom বা Google Meet-এ। স্টুডেন্টরা বাংলাদেশ ও বিদেশ দুই জায়গা থেকেই পড়ে, আর পড়ার ধরন দুটো: **ব্যাচ** আর **ওয়ান-টু-ওয়ান**।

## ১. লক্ষ্য

একাডেমির চারটা মূল কাজ এক জায়গায় আনা:

1. **আয়-ব্যয়ের হিসাব**: কোথা থেকে কত টাকা এলো, কোথায় কত খরচ হলো, আর মাস শেষে লাভ বা ক্ষতি কত।
2. **ফি রিমাইন্ডার**: কার কোন মাসের ফি বাকি, আর স্টুডেন্ট বা অভিভাবককে এক ক্লিকে মেসেজ পাঠানো।
3. **পড়াশোনার প্রগ্রেস**: প্রতিটা পরীক্ষার নম্বর, গ্রেড, উন্নতি বা অবনতি আর র‍্যাংকিং।
4. **এসাইনমেন্ট**: কোন ব্যাচ আর কোন ওয়ান-টু-ওয়ান স্টুডেন্টের দায়িত্বে কোন শিক্ষক।

## ২. গঠন (ফেজ-১, বর্তমান)

```
┌────────────────────────────────────────────┐
│  GitHub রিপোজিটরি (কোড)                    │
│        │  GitHub Pages (ফ্রি হোস্টিং)       │
│        ▼                                    │
│  ব্রাউজারে অ্যাপ (HTML + CSS + JS)          │
│        │                                    │
│        ▼                                    │
│  ব্রাউজারের localStorage (ডেটা)             │
│        │  প্রতিটা পরিবর্তনে অটো-সেভ         │
│        ▼                                    │
│  GitHub PRIVATE রিপো: at-turath-data        │
│  (academy-data.json + প্রতিটা ভার্সনের ইতিহাস)│
└────────────────────────────────────────────┘
রিমাইন্ডার: অ্যাপ → wa.me / sms: / mailto: লিংক → স্টুডেন্ট বা অভিভাবকের WhatsApp, SMS বা ইমেইল
```

- **খরচ:** ০ টাকা।
- **সুবিধা:** কোনো সেটআপ লাগে না, খুব দ্রুত চলে, আর ডেটা অন্য কোথাও যায় না।
- **ডেটা সুরক্ষা:** প্রতিটা পরিবর্তন Private GitHub রিপোজিটরিতে কমিট হয়, আর প্রতিটা কমিট একেকটা পুরোনো ভার্সন। ইন্টারনেট না থাকলে পরিবর্তনগুলো জমে থাকে, সংযোগ ফিরলে নিজে থেকেই সেভ হয়। দুই ডিভাইসে একসাথে পরিবর্তন হলে কোনটা রাখবেন তা জিজ্ঞেস করে, আর অন্যটা ইতিহাসে থেকে যায়।
- **ব্যবহারকারী:** একজন (অ্যাডমিন)। একাধিক ডিভাইস থেকে চালানো যায়।
- **সীমাবদ্ধতা:** শিক্ষকদের আলাদা লগইন নেই, আর SMS স্বয়ংক্রিয়ভাবে যায় না (বাটনে চাপ দিয়ে পাঠাতে হয়)।

## ৩. ডেটা মডেল

```
Teacher ─┐ (teacherId)
         ├──< Batch ──< Student[type=batch] ──< Payment  (মাসভিত্তিক ফি জমা)
         └───────────< Student[type=one2one]             (সরাসরি শিক্ষক, নিজস্ব ফি/সময়/লিংক)
                       Student ──< Exam       (পরীক্ষার ফলাফল)
Transaction  (অন্যান্য আয় / ব্যয় — খাতসহ)
Settings     (একাডেমির নাম, রিমাইন্ডার টেমপ্লেট)
```

| টেবিল | মূল ফিল্ড |
|---|---|
| teachers | name, phone, subject, salary, joinDate |
| batches | name, subject, **teacherId**, days (সপ্তাহের দিন), time, classLink, fee |
| students | name, roll, **type** (batch/one2one), **batchId**, **teacherId**, course, days, time, classLink, monthlyFee, guardian, phone, email, country, admissionDate, status |
| payments | studentId, **month** (কোন মাসের ফি), amount (টাকায়), date, method (বিকাশ/নগদ/রকেট/ব্যাংক/কার্ড/PayPal-Wise-Payoneer) |
| transactions | type (income/expense), category, amount, date, note |
| exams | studentId, title, subject, marks, total, date, remark |
| teacherPayouts | teacherId, amount, date, method, note |

### গুরুত্বপূর্ণ নিয়ম

- **শিক্ষক এসাইনমেন্ট:** ওয়ান-টু-ওয়ান স্টুডেন্টের শিক্ষক হলেন তাঁর নিজের `teacherId` (এটা দিতেই হবে)। ব্যাচের স্টুডেন্টের ক্ষেত্রে নিজের `teacherId` থাকলে সেটা, না থাকলে ব্যাচের শিক্ষক।
- **শিক্ষকের পাওনা:** প্রতিটা ব্যাচে (`payType`, `payValue`) আর প্রতিটা ওয়ান-টু-ওয়ান স্টুডেন্টে নিয়ম ঠিক করা থাকে: `percent` মানে ফি-এর শতাংশ, `fixed` মানে প্রতি স্টুডেন্ট মাসে নির্দিষ্ট টাকা (আংশিক ফি এলে আনুপাতিক)। **স্টুডেন্ট ফি দিলে তবেই** শিক্ষকের অংশ পাওনা হয়, আর ফি যে মাসে আসে সেই মাসের পাওনা ধরা হয়। ফি জমার সময় শিক্ষক আর তাঁর অংশ (`teacherId`, `teacherShare`) পেমেন্টের সাথে সেভ হয়, তাই পরে নিয়ম বদলালে পুরোনো হিসাব বদলায় না। দরকার হলে "নতুন নিয়মে হিসাব করুন" বাটন দিয়ে একটা মাস আবার হিসাব করা যায়।
- **শিক্ষককে পরিশোধ:** `teacherPayouts` (teacherId, amount, date, method, note)। মোট বাকি = সব পাওনা − সব পরিশোধ। বেশি দিলে অগ্রিম হিসেবে দেখায়। পরিশোধ নিজে থেকেই আয়-ব্যয়ে "শিক্ষক সম্মানী" খরচ হিসেবে যোগ হয়।
- **রুটিন:** ব্যাচ আর ওয়ান-টু-ওয়ান, দুই ক্ষেত্রেই ক্লাসের দিন (`days`: ০=রবি … ৬=শনি) আর সময় (`time`, বাংলাদেশ সময়) ঠিক করা থাকে। ফি মাসিক, তবে রুটিন থেকে প্রতি মাসের নির্ধারিত ক্লাসের সংখ্যা বের করা হয়।
- **ফি:** ওয়ান-টু-ওয়ান স্টুডেন্টের ফি আলাদাভাবে লিখতে হয়। ব্যাচের স্টুডেন্টের ফি খালি রাখলে ব্যাচের ফি বসে যায়।
- **মুদ্রা:** সব হিসাব টাকায় হয়। বিদেশি পেমেন্ট যত টাকা হাতে এসেছে সেই অঙ্কে লিখতে হয়।
- **ফোন:** `+` দিয়ে শুরু হলে আন্তর্জাতিক নম্বর ধরা হয়। `01...` দিয়ে শুরু হলে বাংলাদেশি নম্বর (+৮৮০)।
- **বকেয়া হিসাব:** ভর্তির মাস থেকে চলতি মাস পর্যন্ত প্রতি মাসে `monthlyFee` থেকে সেই মাসের মোট জমা বাদ দিলে বাকিটা বকেয়া। নিষ্ক্রিয় স্টুডেন্টদের বকেয়া হিসাব হয় না।
- **আয়:** ফি জমা (payments) আর অন্যান্য আয় (transactions) মিলিয়ে।
- **ব্যয়:** transactions-এর খরচগুলো। শিক্ষকের সম্মানীও এখানেই ব্যয় হিসেবে যায়। শিক্ষক পেজে প্রতিটা শিক্ষকের স্টুডেন্টদের থেকে কত ফি এলো তা দেখায়, তাই শতাংশ হারে সম্মানী হিসাব করা যায়।
- **গ্রেড:** বাংলাদেশি নিয়মে, A+ (৮০+), A (৭০+), A- (৬০+), B (৫০+), C (৪০+), D (৩৩+) আর F।

## ৪. রোডম্যাপ

### ফেজ-২ (দরকার হলে): শিক্ষকদের লগইন
এখন অ্যাডমিন একাই চালান, তাই এটা আপাতত লাগবে না। ভবিষ্যতে শিক্ষকদের নিজেদের নম্বর তোলার দরকার হলে:
- ডেটা যাবে **Supabase**-এ (ফ্রি প্ল্যানে চলবে, PostgreSQL ডেটাবেস)।
- রোলভিত্তিক লগইন থাকবে:
  - **অ্যাডমিন (আপনি):** সবকিছু দেখতে ও করতে পারবেন।
  - **শিক্ষক:** শুধু নিজের ব্যাচের স্টুডেন্ট আর প্রগ্রেস দেখবেন, আর নম্বর দিতে পারবেন। আয়-ব্যয় দেখবেন না।
  - **অফিস স্টাফ:** ফি জমা নেওয়া আর রিমাইন্ডার পাঠানো।
- ফেজ-১-এর ব্যাকআপ ফাইল ইমপোর্ট করে সব পুরোনো ডেটা নতুন সিস্টেমে নেওয়া যাবে।

### ফেজ-৩: অটোমেশন
- প্রতি মাসের নির্দিষ্ট তারিখে বাংলাদেশি SMS গেটওয়ে (যেমন BulkSMSBD বা SSL Wireless) দিয়ে নিজে থেকেই রিমাইন্ডার যাবে। প্রতি SMS-এ প্রায় ২০-৩৫ পয়সা খরচ।
- অভিভাবকদের জন্য আলাদা পোর্টাল থাকবে, যেখানে তাঁরা সন্তানের রেজাল্ট আর ফি-এর অবস্থা দেখতে পারবেন।
- বিকাশ, নগদ বা কার্ড দিয়ে অনলাইনে ফি নেওয়া যাবে।
- উপস্থিতি (অ্যাটেনডেন্স) ট্র্যাকিং যোগ হবে। মিস করা ক্লাস আর মেকআপ ক্লাসের হিসাবও রাখা যাবে।
- টাইমজোন সাপোর্ট আসবে, যাতে বিদেশি স্টুডেন্টরা ক্লাসের সময় নিজের দেশের সময়ে দেখতে পান।
