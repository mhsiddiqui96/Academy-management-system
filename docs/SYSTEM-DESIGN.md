# সিস্টেম ডিজাইন (খসড়া)

## ১. লক্ষ্য

একাডেমির চারটা মূল কাজ এক জায়গায় আনা:

1. **আয়-ব্যয়ের হিসাব**: কোথা থেকে কত টাকা এলো, কোথায় কত খরচ হলো, আর মাস শেষে লাভ বা ক্ষতি কত।
2. **বেতন রিমাইন্ডার**: কার কোন মাসের বেতন বাকি, আর অভিভাবককে এক ক্লিকে মেসেজ পাঠানো।
3. **পড়াশোনার প্রগ্রেস**: প্রতিটা পরীক্ষার নম্বর, গ্রেড, উন্নতি বা অবনতি আর র‍্যাংকিং।
4. **এসাইনমেন্ট**: কোন ব্যাচ বা স্টুডেন্টের দায়িত্বে কোন শিক্ষক।

## ২. গঠন (ফেজ-১, বর্তমান)

```
┌────────────────────────────────────────────┐
│  GitHub রিপোজিটরি (কোড)                    │
│        │  GitHub Pages (ফ্রি হোস্টিং)       │
│        ▼                                    │
│  ব্রাউজারে অ্যাপ (HTML + CSS + JS)          │
│        │                                    │
│        ▼                                    │
│  ব্রাউজারের localStorage (ডেটা)             │
│        │  সাপ্তাহিক ব্যাকআপ (.json)         │
│        ▼                                    │
│  Google Drive / পেনড্রাইভ                   │
└────────────────────────────────────────────┘
রিমাইন্ডার: অ্যাপ → wa.me / sms: লিংক → অভিভাবকের WhatsApp/SMS
```

- **খরচ:** ০ টাকা।
- **সুবিধা:** কোনো সেটআপ লাগে না, খুব দ্রুত চলে, আর ডেটা অন্য কোথাও যায় না।
- **সীমাবদ্ধতা:** ডেটা এক ডিভাইসে থাকে, লগইন নেই, আর SMS স্বয়ংক্রিয়ভাবে যায় না (বাটনে চাপ দিয়ে পাঠাতে হয়)।

## ৩. ডেটা মডেল

```
Teacher ─┐ (teacherId)
         ├──< Batch ──< Student ──< Payment   (মাসভিত্তিক বেতন জমা)
         └───────────< Student                (আলাদা শিক্ষক, ঐচ্ছিক)
                       Student ──< Exam       (পরীক্ষার ফলাফল)
Transaction  (অন্যান্য আয় / ব্যয় — খাতসহ)
Settings     (একাডেমির নাম, রিমাইন্ডার টেমপ্লেট)
```

| টেবিল | মূল ফিল্ড |
|---|---|
| teachers | name, phone, subject, salary, joinDate |
| batches | name, subject, **teacherId**, schedule, fee |
| students | name, roll, **batchId**, **teacherId** (ঐচ্ছিক), monthlyFee, guardian, phone, admissionDate, status |
| payments | studentId, **month** (কোন মাসের বেতন), amount, date, method (ক্যাশ/বিকাশ/নগদ/রকেট/ব্যাংক) |
| transactions | type (income/expense), category, amount, date, note |
| exams | studentId, title, subject, marks, total, date, remark |

### গুরুত্বপূর্ণ নিয়ম

- **শিক্ষক এসাইনমেন্ট:** একজন স্টুডেন্টের শিক্ষক বলতে বোঝায় তাঁর নিজের `teacherId`। সেটা খালি থাকলে তাঁর ব্যাচের শিক্ষককে ধরা হয়।
- **বকেয়া হিসাব:** ভর্তির মাস থেকে চলতি মাস পর্যন্ত প্রতি মাসে `monthlyFee` থেকে সেই মাসের মোট জমা বাদ দিলে বাকিটা বকেয়া। নিষ্ক্রিয় স্টুডেন্টদের বকেয়া হিসাব হয় না।
- **আয়:** বেতন জমা (payments) আর অন্যান্য আয় (transactions) মিলিয়ে।
- **ব্যয়:** transactions-এর খরচগুলো। শিক্ষকের বেতনও এখানেই ব্যয় হিসেবে যায়।
- **গ্রেড:** বাংলাদেশি নিয়মে, A+ (৮০+), A (৭০+), A- (৬০+), B (৫০+), C (৪০+), D (৩৩+) আর F।

## ৪. রোডম্যাপ

### ফেজ-২: অনলাইন ডেটাবেস ও লগইন (যখন একাধিক মানুষ একসাথে ব্যবহার করবেন)
- ডেটা যাবে **Supabase**-এ (ফ্রি প্ল্যানে চলবে, PostgreSQL ডেটাবেস)।
- রোলভিত্তিক লগইন থাকবে:
  - **অ্যাডমিন (আপনি):** সবকিছু দেখতে ও করতে পারবেন।
  - **শিক্ষক:** শুধু নিজের ব্যাচের স্টুডেন্ট আর প্রগ্রেস দেখবেন, আর নম্বর দিতে পারবেন। আয়-ব্যয় দেখবেন না।
  - **অফিস স্টাফ:** বেতন জমা নেওয়া আর রিমাইন্ডার পাঠানো।
- ফেজ-১-এর ব্যাকআপ ফাইল ইমপোর্ট করে সব পুরোনো ডেটা নতুন সিস্টেমে নেওয়া যাবে।

### ফেজ-৩: অটোমেশন
- প্রতি মাসের নির্দিষ্ট তারিখে বাংলাদেশি SMS গেটওয়ে (যেমন BulkSMSBD বা SSL Wireless) দিয়ে নিজে থেকেই রিমাইন্ডার যাবে। প্রতি SMS-এ প্রায় ২০-৩৫ পয়সা খরচ।
- অভিভাবকদের জন্য আলাদা পোর্টাল থাকবে, যেখানে তাঁরা সন্তানের রেজাল্ট আর বেতনের অবস্থা দেখতে পারবেন।
- বিকাশ বা নগদ দিয়ে অনলাইনে বেতন নেওয়া যাবে।
- উপস্থিতি (অ্যাটেনডেন্স) ট্র্যাকিং যোগ হবে।
